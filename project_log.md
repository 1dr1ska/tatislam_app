## Текущее состояние (после фаз 1–2)

### Supabase backend
- Нормализованная схема с таблицами `profiles`, `sections`, `publications`, `content_blocks`, `publication_sections` (см. мрации `0001`–`0009`).
- RLS-политики используют helper `is_admin()` — публичное только чтение, админ-роль получает полный CRUD.
- Хранилище: единый bucket `media` с иерархией `covers/`, `blocks/<publicationId>/(images|audio|video)/`; в базе сохраняются только storage path.
- Документация и пошаговая инструкция: `SUPABASE_SETUP.md` (актуальна).

### Flutter data/domain слой
- Реализованы сущности `Publication`, `PublicationDetail`, `ContentBlock` (Text/Image/Video/Audio), сопутствующие модели и репозитории.
- Репозитории подключены через Riverpod-провайдеры; добавлены сервисы автоопределения видео-провайдера и локального хранения layout-настроек.
- `pubspec.yaml` дополнен зависимостями (`file_picker`, `webview_flutter` и др.), `flutter analyze` проходит на слое data/domain.

### Presentation слой (UI)
- Текущие UI-экраны (Home, Catalog, Search, Favorites, Publication Detail, Admin) ещё не переписаны под новую доменную модель.
- Старый код опирается на устаревшие поля (`type`, `content`, `mediaUrl`) и временно несовместим до завершения Phase 3+.

## Детальное видение клиентской части (Phase 3–5)

### 1. Главная (Home) — два режима

**Feed (по умолчанию, «соцсеть»):** — бесконечная вертикальная лента с постраничной подгрузкой (10–12 элементов за раз), прокручивается свайпами вверх/вниз, вся карточка tappable (и кнопка «Читать →») ведёт на экран публикации.

```
┌────────────────────────────────────────────┐
│ Cover 16:9 (Hero)                          │
├────────────────────────────────────────────┤
│ 🏷 Section Chips   📅 Date   ★ Favorite    │
│ #Type Badge (из корневого раздела)          │
├────────────────────────────────────────────┤
│ H1 Title (max 2 строки)                    │
│ BodyLarge Description (3–4 строки)         │
├────────────────────────────────────────────┤
│ Actions: [Читать →] [Поделиться]           │
└────────────────────────────────────────────┘
```

- Вертикальный список с `SliverAppBar` и `RefreshIndicator`.
- Плавные появления карточек (implicit animations) + Hero-переход обложки → detail.
- `HomeViewModel` держит `AsyncValue<List<Publication>>` и `HomeLayoutMode`.

**Cards/Grid (классика):** — статичная сетка прямоугольных карточек (2–3 колонки), каждая карточка целиком ведёт на детальную статью по тапу.

```
┌───────────────┐ ┌───────────────┐
│ 4:3 Cover     │ │ 4:3 Cover     │
│───────────────│ │───────────────│
│ Title         │ │ Title         │
│ Description…  │ │ Description…  │
│ 📅 Date  ★     │ │ 📅 Date  ★     │
└───────────────┘ └───────────────┘
```

- 2–3 колонки в зависимости от ширины (`ResponsiveBreakpoints`), ленивый грид с постраничной подгрузкой.
- Переключатель `SegmentedButton<Mode>` в `PinnedAppBar`; фильтры не прилипают отдельно, управление остаётся в верхней панели.

### 2. Catalog / Search / Favorites

- Общий reusable widget `PublicationGrid` c stateful behavior (loading/empty/error).
- Верхняя панель:

```
┌────────────────────────────────────────────┐
│ [SearchField...............] [Filter ⚙]    │
│ Sections: [Все] [Намаз] [История] [...]    │
└────────────────────────────────────────────┘
```

- Catalog: иерархический выбор разделов (до 3 уровней, но поддерживаем 1–2) + сортировка («Новые», «Популярные»). Для навигации показываем хлебные крошки.
- Search: live suggestions (debounce) на клиенте + запросы автодополнения в Supabase (RPC) по title/description; результаты в том же grid.
- Favorites: локальный провайдер, отображает grid с статусом «Offline ready»; при наличии обновлений подтягивает свежую версию из сети.
- Во всех трёх экранах карточки показывают прогресс скачивания (если идёт) и размер до старта загрузки.

### 3. Publication Detail

```
┌──────────────────────────────────────────────┐
│ Hero Cover (blurs into background gradient) │
│ Title (DisplayLarge)                        │
│ Chips: sections + type + date               │
│ Action Row: [★ Favorite] [⇪ Share]          │
├──────────────────────────────────────────────┤
│ Content Blocks (ordered):                    │
│ ① TextBlock → adaptive typography            │
│ ② ImageBlock → tap = fullscreen viewer       │
│ ③ VideoBlock → inline player, без floating   │
│ ④ AudioBlock → `just_audio` mini-player      │
│    (плавающая панель с play/pause)           │
│ ...                                          │
└──────────────────────────────────────────────┘
```

- Skeleton state (shimmer) для header + блоков.
- Error state с retry и fallback текстом.
- `PublicationDetailViewModel` orchestrates load, handles `ContentBlock` mapping → виджеты, поддерживает фоновое аудио через `audio_service` + `just_audio` (iOS background modes, Android notification).
- ImageBlock допускает несколько изображений → горизонтальный карусель/галерея с fullscreen-просмотром и пролистыванием.

**Общий каркас:**

```
┌────────────────────────────────────────────┐
│ AdminShell TopBar (brand, user, logout)    │
├──Sidebar───────────────────────────────────┤
│ ▸ Dashboard (future)                       │

```

**Publications List:** DataTable + toolbar

```
┌Toolbar────────────────────────────────────┐
│ [ + New Publication ]  [Search ...] [Sort] │
└────────────────────────────────────────────┘
┌DataTable─────────────┬───────────────┬────┐
│ □ | Title            | Status | Date | ⋮ │

```

- Bulk actions (delete, hide), status badges («Draft», «Published»).
- Inline indicators, если публикация не имеет секций/обложки.

**Publication Editor (wizardless, single page):**

```
┌Metadata Card──────────────────────────────┐
│ Title [_____________________________]      │
│ Description [Multi-line Editor......]      │
│ Cover: [Upload]  Preview                  │
│ Sections: [✓ Намаз] [✓ История] [...]     │
│ Publish toggle + date picker              │
└────────────────────────────────────────────┘

┌Blocks Canvas──────────────────────────────┐
│ [+ Text] [+ Image] [+ Video] [+ Audio] [+ Link] │
│-------------------------------------------│
│ ⋮ Text Block                              │
│    [RichTextEditor......................] │
│    [Attach Link] → (Текст, URL)           │
│-------------------------------------------│
│ ⋮ Image Block                             │
│    Gallery: [ + Add Photo ] ×N            │
│    Caption [_____________]                │
│    [Replace] [Fullscreen Preview]         │
│-------------------------------------------│
│ ⋮ Audio Block                             │
│    Upload progress + waveform preview     │
│    [Enable background playback ✓]         │
│-------------------------------------------│
│ [Publish] [Preview] [Delete Draft]        │
└────────────────────────────────────────────┘
```

- Drag handle `⋮` для ReorderableListView; fallback кнопки ↑/↓ для клавиатуры. Порядок сохраняется мгновенно на сервер.
- При добавлении Image/Audio/Video — перед стартом показываем размер файла; загрузка в Supabase с прогрессом прямо в карточке блока и в превью-тайле.
- Video: выбор между «Upload file» (Supabase Storage, mp4) и «External URL» (YouTube, RuTube, VK, др.) с автоопределением провайдера.
- Text блок: встроенная кнопка «Attach Link» (label + URL); на клиенте ссылки выделяются цветом и открываются во внешнем браузере.
- Validation summary (панель справа) показывает блоки с ошибками; автосохранение выполняется на сервер при каждом изменении, состояние публикации — Draft до явного «Publish».

**Sections Management:**

```
┌Toolbar────────────────────────────────────┐
│ [ + New Section ]                          │
└────────────────────────────────────────────┘
┌Sortable List──────────────────────────────┐
│ ⋮ Намаз        | Visible ✓ | Parent: — | Edit | Delete │
│    └─ ⋮ Подраздел 1 | Visible ✓ | Edit | Delete │
│        └─ ⋮ Подраздел 2 | Visible ✓ | Edit | Delete │
└────────────────────────────────────────────┘
```

- Drag-and-drop order с auto-save, структура дерева до 3 уровней (parent_id). В Edit drawer можно выбрать родителя и статус видимости.
- При удалении раздела предупреждаем о последствиях (удаление/перемещение дочерних разделов).
- Material 3 theme: `ColorScheme.fromSeed`, typography scale (Display → Label), Elevated/Outlined/Segmented buttons.
- Consistent `PageScaffold` shell с AppBar/NavigationRail на больших экранах.
- Error & empty states: иллюстрации + call-to-action.
- Localization: UI на татарском, допускаем русские термины при отсутствии распространённого аналога (все строки централизованы в `AppStrings`).
- Accessibility: min tappable area 48dp, семантические роли для блоков контента, учёт фонового аудио контроллера.
- Offline: пользователи могут загружать публикации (контент + медиа) на устройство вручную; показываем диалог с размером, прогресс в карточках и обновляем кеш при появлении новой версии.
- Notifications: при публикации можно отправить push (по умолчанию включено, админ может отключить чекбоксом). Используем Firebase Cloud Messaging для iOS/Android.
- Тестирование: планируем widget/integration тесты для публикаций с RuTube-видео, Supabase-хостингом видео и аудио, а также для offline-загрузок и фонового аудио.

## Дополнительные уточнения (2026-07-15)

- **Type badge**: выводим по корневому разделу выбранной иерархии. При необходимости будущего расширения предусмотрим опциональное поле `display_type`, но по умолчанию используем название верхнего уровня.
- **Sticky UI**: переключатель режимов и фильтры находятся в закреплённом `AppBar`; дополнительных "липких" панелей не требуется.
- **Auto-suggest**: поиск с автодополнением реализуем через Supabase RPC, результаты отображаем в общем grid.
- **Hierarchical sections**: поддерживаем до 3 уровней вложенности (`parent_id` в таблице `sections`), UI отображает дерево с хлебными крошками.
- **Offload/Offline**: скачивание публикаций инициируется пользователем; до старта показываем размер, после — статус «Offline ready». При появлении новых версий обновляем локальную копию.
- **Audio mini-player**: реализуем плавающую панель воспроизведения для аудио (play/pause) + поддержка background playback (iOS background mode, Android notification).
- **Image galleries**: один блок может содержать несколько изображений; в detail — карусель, в fullscreen — пролистывание жестами.
- **Autosave strategy**: каждое изменение в редакторе сразу persist'ится в Supabase как Draft (без локального хранения). Есть кнопка «Delete Draft» с подтверждением.
- **Link attachments**: админ добавляет ссылки через отдельную кнопку в текстовом блоке (label + URL); у пользователей ссылки выделяются цветом и открываются во внешнем браузере.
- **Downloads & progress**: индикаторы прогресса показываются и в списковых карточках, и в detail; скачивание начинается только после подтверждения пользователя.
- **Notifications**: при публикации по умолчанию отправляем push через FCM; у админа переключатель «Отправить уведомление».
- **Тесты**: обязательно покрываем видео из внешних (RuTube/VK) и Supabase источников, а также аудио из Supabase и offline-режим.
- Localization: расширяем текущий `AppStrings` для новых текстов.
- Accessibility: min tappable area 48dp, семантические роли для блоков контента.
